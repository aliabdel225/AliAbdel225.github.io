01 / Executive Brief

To: IT Operations Manager
From: Infrastructure & Security Administrator
Subject: Phase 0 delivery and operational risk

Manager, the assignment was to turn a home lab into a functioning IT department. Naturally, the infrastructure chose to demonstrate every reason engineers keep incident logs.

We deployed a Windows Server 2025 Active Directory domain controller, connected it to a physical Kali Linux workstation through bridged virtualization, configured Samba Winbind and Kerberos, and achieved a successful graphical login using a domain account. The domain controller now runs under a persistent systemd-managed VirtualBox headless process rather than depending on an interactive desktop session.

Outcome: Initial deployment objectives met. Backup, controlled shutdown, reboot recovery, and broader endpoint onboarding are not yet production-validated. A system that works once is a demonstration; a system that survives failure is engineering.

Active Directory and network integration

Existing Windows Server lab infrastructure contained directory identities, groups, OUs and documented policy snapshots. The VM was moved from isolated VirtualBox networking to a bridged wireless adapter. Kali was configured to use the domain controller for DNS and to resolve domain identities through Winbind.

04 / Incident Register

HOME-INC-001 · RESOLVED IN TEST

Graphical domain login failure

Symptom: Terminal-based Kerberos and PAM checks passed, but the graphical login returned to the prompt. LightDM recorded NT_STATUS_NO_LOGON_SERVERS.

Investigation: Verified identity resolution, Kerberos, PAM, home-directory permissions, session configuration and Winbind. The VM was originally launched as a graphical VirtualBox process under the local desktop user.

Corrective action: Migrated the domain controller to a systemd-managed VBoxHeadless process with user lingering. Validation: Domain login succeeded after local graphical logout, and the original user's systemd manager still contained the VM process.

HOME-INC-002 · RESOLVED

VirtualBox session lock

Error: VBOX_E_INVALID_OBJECT_STATE when attempting headless startup while the VM was already running in a graphical session.

Resolution: Gracefully shut down Windows through its planned GUI shutdown option, confirmed the VM was powered off, then started it in headless mode. Turns out one VM cannot occupy two execution sessions simultaneously. Wild concept.

HOME-INC-003 · RESOLVED IN TEST

Transient domain discovery failure

Error: WBC_ERR_DOMAIN_NOT_FOUND immediately after systemd started the VM.

Resolution: Checked bridged interface, DNS configuration and domain-controller hostname resolution. NETLOGON succeeded after Windows services had time to initialize. VM running is not the same as directory services ready.

HOME-SEC-001 · EXPECTED SECURITY BEHAVIOR

Domain account denied sudo

The domain user authenticated successfully but was not listed in Linux sudoers. No blanket privilege escalation was granted. A later phase will design role-based administration through a dedicated security group.

HOME-OPS-001 · OPEN

ACPI shutdown reliability

A VirtualBox ACPI power-button request did not complete the Windows shutdown during initial testing; Windows was shut down through the guest GUI instead. The current stop helper requests ACPI shutdown and polls VM state, but a full host-shutdown test has not been completed.

05 / Availability Engineering

To remove the interactive desktop dependency, the VM was started using the actual VirtualBox headless executable from a systemd user service. User lingering allows the service manager to continue running after logout.

[Unit]
Description=AD Domain Controller VM

[Service]
Type=exec
ExecStart=/usr/lib/virtualbox/VBoxHeadless --startvm <REDACTED-UUID>
ExecStop=%h/.local/bin/<shutdown-helper>.sh
TimeoutStopSec=300
Restart=on-failure
RestartSec=15

[Install]
WantedBy=default.target

Verified: Service enabled and active; user lingering enabled; VBoxHeadless tracked under the service cgroup; domain controller reachable; graphical domain login successful after logout.

Not yet verified: Automatic recovery after host reboot and safe shutdown of the Windows guest during full host power-off. The default KillMode=control-group introduces a risk of process termination if guest shutdown does not finish in time.

07 / Management Conclusion

The infrastructure now demonstrates real cross-platform identity engineering: a Windows Server domain controller authenticating a physical Linux workstation with Winbind, PAM and Kerberos, supported by a persistent virtualized service architecture.

We did not solve the incident by reinstalling everything or giving everyone administrator privileges. We traced the failure across authentication, DNS, virtualization and service lifecycle boundaries, corrected the dependency, and verified the outcome.

Now we document it, back it up, monitor it, and make it recoverable. Because the only thing more embarrassing than a broken system is a broken system nobody knows how to restore.

Manager recommendation: Approve the infrastructure documentation phase and prioritize backup and shutdown safety before expanding household domain enrollment.
